# TH06 エンジンの構造と、PS3移植で判ったこと

この文書だけは母艦(Claude)の書き下ろしで、他のdocsのような知識ベースのコピーではない。
PS3移植 (`~/th06_ps3`、2026-07完成・実機60fps) で実際に踏んだ地面の記録だと思って読め。

## 1. 出自と系譜 (ライセンスと素性)

```
GensokyoClub/th06 portable branch @9a1c50b   ← 東方紅魔郷1.02fのデコンパイル (GPLv3)
        └─ ~/th06_ps3            (PS3 direct GCM移植、非公開の作業ツリー)
                └─ ~/th06_ps3_public  (engine only の公開版、GitHub: kan8223-dotcom/th06_ps3)
                        └─ このrepoの src/ shim/   ← ここからのコピー (2026-08-03)
```

- ライセンスは **GPLv3** (`LICENSE`)。派生物も同じ条件で出すこと。
- **原作データ (DAT/WAV) は絶対に同梱しない。** ユーザー自身の製品盤から供給させる設計を守れ。
  PS3版は製品CDを実機に挿させて照合する方式を取った (`~/th06_ps3/ps3/cdauth.cpp`)。
  この方式はPS3のLV1一時解除に依存しており **PSPにはそのまま持ち込めない**。
  PSPでのデータ供給方法は技術以前に配布形態の判断なので、**田中に決めさせろ。勝手に決めるな。**
- `src/` からGL系バックエンド (`FixedFunctionGL` / `WebGL` / `GLFunc`) と
  他プラットフォームのMIDI (`MidiAlsa` / `MidiCoreAudio` / `MidiWin32`) は引き渡し時に削除済み。

## 2. アーキテクチャ: engineは触るな、shimとbackendを書け

```
src/            プラットフォーム非依存のゲーム本体。上流decompとの差分を最小に保て。
shim/sdl_stub.cpp   SDL2 APIの最小自前実装。engineはSDLを呼んでいるつもりでここに来る。
ps3/*.cpp       (PS3版) 実際のハード叩き。→ PSP版では psp/*.cpp を新規に書く。
```

engineを直接書き換えると上流との差分が増えて、後で原作挙動との照合ができなくなる。
PS3版はこの規律を守ったおかげで「魔理沙Bのボム中ショット停止」がバグではなく原作仕様だと
git logで証明できた。**同じ規律を守れ。**

PSPで新規に書く必要がある口はこれだけある (PS3版の対応ファイルが手本):

| 役目 | PS3版の実装 | PSPでの見当 |
|---|---|---|
| 画面出力・描画 | `ps3/video.cpp`, `ps3/RsxGfx.cpp` | sceGu (GU) で書くのが本命 |
| 入力 | `ps3/pad.cpp`, `ps3/kb.cpp` | sceCtrl → SDLキーステート配列に詰める |
| 音声出力 | `ps3/audio_out.cpp` (リングバッファ) | sceAudio のチャンネル出力 |
| ファイルIO | `shim/sdl_stub.cpp` のRWops | ms0:/ 経由。UMDは考えるな |
| セーブ | `ps3/savedata.cpp` (PS3純正SaveData) | ms0上のファイルで足りるはず |

**入力の型は「パッドを読んでSDLのキーステート配列を埋める」**という形になっている
(`shim/sdl_stub.cpp` の `SDL_GetKeyboardState`)。engineはキーボードを見ているつもりで動く。
PSPも同じ型に嵌めれば engine 側は無改造で済む。

## 3. 描画: 最初に決める1点は解像度

- グラフィックは `src/graphics/GfxInterface.hpp` の抽象越し。`Software.cpp` が純CPUラスタライザで、
  これは**どのプラットフォームでも動く保険**として使える (PS3でも初期はこれで絵を出した)。
- ゲームの内部解像度は **640x480**。PSPの画面は **480x272**。ここをどう埋めるかが最初の設計判断で、
  絵の出し方も性能も全部これに引きずられる。**着手前に決めろ。**
- PS3実測の教訓: **全表示モードを1080pで直接ラスタライズしたらフィルレートが6.75倍**になって
  処理落ちした。640x480のRTに描いて最後に1回だけ拡大blitする形に変えて解決した。
  PSPでも「内部640x480に描いて縮小」か「最初から480x272で描く」かで負荷が全く変わる。

## 4. 音声: 自前ミキサの地雷は既に2つ踏んである

`src/SoundPlayer.cpp` は SDL_mixer を使わず自前でミックスして `SDL_QueueAudio` に流す
(原作がサンプル精度のループ点を要求するため)。**2026-08-03に実機で潰したバグを2件、
このコードは既に含んでいる。同じ穴を掘り直すな。**

1. **BGMをRAMへ全部プリロードしろ。** ミキサのmutex内でサンプル毎にディスクを読むと、
   PS3実機で 11〜123ms のストールが出て音が途切れた。`LoadWav` が data チャンクを
   一括読みする形になっているのはそのため。**PSPのメモリースティックはHDDより遅い。
   同じことをやったら即死する。**
2. **ループ折り返しの書き込み位置。** インタリーブのミックスバッファでフレームNは `2*N` から。
   上流は `samplesMixed + 2*j` と書いていて、ループ点を含むブロック全体が壊れていた
   (ホスト照合で7.7〜92.9ms相当が参照と不一致)。修正済みの形が入っている。
3. `LoadPos` のループ点公開はmutex内。`pos > loopEnd` になると `loopEnd - pos` が
   u32アンダーフローしてバッファ外を読む。

その他:
- **SEの同時発火は3枠まで** (`soundBuffersToPlay[3]`) で、溢れたら捨てる。これは**原作仕様**。
  実機で死亡SE(ピチューン)が消える疑いを追ったが、5/5で正常再生を確認して無罪だった。
- ミキサの出力は `max(8, 同時ch数)` で割る。原作のDirectSoundには無い処理だが、
  BGMもSEも同じ係数で割るので相対バランスは保たれる。
- **MIDIモード (`src/midi/MidiDefault.cpp` = TinySoundFont) は PSPでは要判断。**
  PS3版が使ったSF2 (TimGM6mb) は **5.7MB** ある。PSP-1000は本体RAM 32MBで、
  ゲーム本体+原作データと同居できるか怪しい。**先にメモリ収支を計算しろ。**
  引き渡しrepoにSF2は入れていない (実体: `~/th06_ps3_public/assets/soundfont/`)。

## 5. エンディアン: PS3の名残を探して落とせ

**PS3はビッグエンディアン、PSPのMIPSはリトルエンディアン。**
PS3移植では原作データ(LE)を読むためにバイトスワップを入れた箇所がある。PSPでは
これらは no-op になるのが正しい (`SDL_SwapLE*` はLE機で恒等) が、**マクロを経由せず
手書きでスワップしている箇所があれば逆に壊れる。**

引き渡し時点でスワップに触っているファイル:
`src/SoundPlayer.cpp`, `src/MidiOutput.cpp`, `shim/SDL2/SDL_shim.h`

`SDL_shim.h` のスワップマクロがどちらのエンディアンでも正しいかを**最初に確認しろ。**
PS3向けに「常にスワップする」実装になっていたら、PSPでは全データが壊れる。

## 5.5 最初の1時間で必ずぶつかる問題: `TH06_PS3` マクロ

引き渡したソースは **PS3移植の途中形** であり、プラットフォーム分岐が `TH06_PS3` マクロで
書かれている。**18ファイル・103箇所**ある (`grep -rn TH06_PS3 src shim`)。

PSPビルドでは `TH06_PS3` が未定義になるため、**PS3向けに閉じてあった穴が開く**。判明している実例:

- `src/GameWindow.cpp:93` — `#ifndef TH06_PS3` でGLバックエンドを include している。
  PSPでは条件が真になり、**削除済みの `FixedFunctionGL.hpp` / `WebGL.hpp` を掴んでビルドが落ちる。**
  同ファイルのバックエンド表 (`s_RenderBackends`) も同じ条件で切り替わる。
- `src/MidiOutput.hpp:11` — こちらは `_WIN32` / `LIBASOUND_MIDI_SUPPORT` /
  `COREAUDIO_MIDI_SUPPORT` の分岐で、どれも立たなければ `MidiDefault.hpp` に落ちる。
  **PSPではこのまま正しく動く** (要らないなら別途切れ)。

**設計判断**: `TH06_PSP` を新設して各分岐を三分岐にするか、`TH06_PS3` を
「ネイティブ機バックエンド有り」を意味する汎用マクロに読み替えるか。
103箇所の中身を読んでから決めろ。PS3固有 (GCM/RSX/CD照合/XMB) と、
汎用のネイティブ機向け分岐 (SDL不在、ファイルパス、スレッド優先度) が混在している。

## 6. 性能の目安と、PS3で潰した3大要因

PS3の最終形は **実機60fps・処理落ち率0.7%・エンディング完走**。そこに至るまでに潰した3つ:

1. 敵スペル名の**初回CJKグリフ生成**が 46〜95ms × 14件 → 事前生成/キャッシュで0に
2. **SE開始時のミキサmutex待ち** 最大49ms × 15件 → 0.005msに
3. **フィルレート** (前述の1080p直描き) → 固定RT+拡大blitで解決

PSPのCPUは 333MHz (初期は222MHz制限) の MIPS で、PS3のPPUとは比較にならない。
**「たぶん重い」で作り込む前に測れ。** PS3移植でも、想像した犯人はことごとく外れて、
実測が毎回別の犯人を指した。
